# HCI design life cycle

HCI studies how people interact with computing systems. User experience includes how useful, understandable, efficient, and satisfying a product feels in its context. A usable screen is not sufficient if it solves the wrong problem.

The workflow is iterative: **understand context → define requirements → design alternatives → prototype → evaluate → refine**. Evaluation may send the project back to requirements or context research.

| Stage | Activity | Output in this exercise |
| --- | --- | --- |
| Understand context | Identify users, goals, devices, constraints | Assumed novice multilingual readers using the Wikipedia desktop portal; confirm through interviews later |
| Define requirements | Turn needs into observable outcomes | Find a language without knowing its article-count category; see the active search language |
| Design alternatives | Sketch possible solutions and tradeoffs | Full language label, searchable directory, visible all-languages route |
| Prototype | Make ideas concrete at suitable fidelity | Editable SVG and Figma board with two static screens |
| Evaluate | Inspect heuristics and observe representative users | Initial expert inspection completed; participant study planned |
| Refine | Prioritize evidence and repeat | Validate language discoverability before adding visual polish |

## Requirements for the proposed redesign

- R1: Display the search language as a full name before submission (finding U1).
- R2: Offer language filtering using native and English names, with an A-Z list (U2).
- R3: Keep a clear route to all languages near the primary search task (U3).
- R4: Provide cancel/back navigation without discarding the query or selected language.

These are proposed requirements, not validated user needs. Adding language filtering could help discovery but needs careful multilingual matching and keyboard interaction. The two-screen board describes that intent without implementing it.

## Learning reflection prompts

Explain why evaluation occurs throughout the cycle. Describe how an observed interface feature differs from an inferred usability problem. Try editing one Figma text layer and explain which requirement it serves. The student should answer these personally; prepared notes alone do not demonstrate understanding.
